# 操作流程

本页只说明如何操作；字段定义见 `data-format.md`，内部职责见 `architecture.md`。

顶部七个标签分别对应实时采集、选择原始子任务、录制微调、六步标定、单手处理、双手只读回放和全局导出队列。同一时刻仅显示一个模块；切换只隐藏面板，保留连接、输入、微调参数和任务。支持方向键及Home/End，窄屏标签栏横向滚动。默认打开子任务选择；导入时切到微调加载进度，打开结果时切到只读回放，提交导出后切到队列。

## 实时全流程：插上手套后从这里开始

1. 选择采集模式，刷新设备并选中实际USB序列号。默认**DGST完整采集**需要正常相机；相机无法探测时，选择**仅编码器兼容（无需相机）**，直接连接ADB调试设备，不点“启用板端采集”。
2. 仅DGST模式：调试设备先点**启用板端采集**，已有DGST接口则跳过。操作只调用板端已安装程序：USB会短暂重连，ECM暂时移除，RTSP让出相机给DGST；视频排空但不保存。兼容模式只读板端已有`ma782-read`，不启动相机/DGST，不重配USB。不部署固件、不写板端零位；缺少所需程序时明确报错，不自动刷机或切换模式。
3. 按实际佩戴点击常显的**左手**或**右手**按钮，再点击**连接所选手套**，页面自动进入实时手套模式。模型、标定与录制以用户选择为准；设备声明只作提示，声明相反也允许连接，不修改板端配置或原始CS接线。连接期间按钮锁定；要换手侧，先停止录制并断开，再选择手侧重新连接。断连或旧帧会禁用采样并隐藏过期预览。
4. 新建标定。按六组提示摆好本组零位，勾选姿态确认，然后采集。每次只收集点击之后约1.5秒的新样本；保持静止直到结束。切换分组后必须重新确认姿态。
5. 完成六组后做明确的屈伸动作，检查模型方向，必要时修改对应通道的 `+1/-1`；保存到固定标定目录。采样稳定只说明静止，不证明零位姿态正确。
6. 选择当前设备已保存的完整标定，点击**开始动作录制**，完成动作后点击**停止并导入**。录制使用独立连续接收，不会因网页预览刷新较慢而主动抽帧。原始数据及元数据保存在 `data/raw/` 唯一目录。
7. 停止成功后录制自动导入离线处理区；选择匹配标定开始处理，然后在三栏回放查看结果。录制过程不运行全帧Hand2求解，正式计算在录制完成后执行。

正式零位必须由操作者根据实物姿态确认。未保存完整标定不能开始动作录制。断连/接收失败会保留未完成证据，不把它当作已完成录制；重连会清除网页中的旧会话草稿。停止录制后仍保持实时连接，可继续录下一段；断开只停止本工具的数据会话，不自动关闭板端程序或恢复RTSP。

实时区始终展开 J1～J21 的圆形指针码表。左右统一：J1～J5侧摆、J6～J10掌骨屈伸、J11～J15次末节屈伸、J16～J20末端屈伸，各组从拇指到小拇指排列，J21为小拇指CMC。左右手分别按自己的CS表取值，每张码表显示中文关节标签、物理CS和对应原始列，悬停标题可查看URDF关节名。原始绝对角0°在正上方、顺时针递增，不应用预览零位或方向，0°也是有效读数。断连、映射缺失或最新帧超过1秒时隐藏指针与历史数值；三维模型预览仍保留。

兼容模式在页面明确显示“软件生成 device_id”、真实 `board_device_id`、元数据来源和通道映射来源。软件ID由真实SoC序列号稳定生成，重连/重启不变，但与DGST设备ID不同；不要改名借用旧ID的标定。优先使用校验通过的出厂接线；只有出厂记录确实不存在时才采用用户所选手侧配置，并标为未核验，须操作者确认实际接线。损坏或设备身份冲突的出厂记录不会回退。仍需实物完成六步零位和方向确认。

左右手只统一J的解剖含义，不共用接线、零位、方向或比例。修改某侧通道对应只维护该侧CS表，不改变共同关节定义。标定页按标准J显示，原始值、零位和方向会定位到同一物理CS；不要按原始列中同名的J猜测关节。旧错误定义下确认过的拇指方向请重新核对：J1应驱动侧摆，J6应驱动掌骨屈伸。

兼容模式约每10毫秒读取驱动最新扫描，实际频率受ADB影响；保留每次交付的真实扫描号，可能跳过中间物理扫描。页面“主机交付序号”连续不代表物理扫描无丢失。

以下是已有录制的离线入口；后面的保存、处理和回放规则两种模式共用。

## 1. 导入已有录制

原始录制文件始终只读。工作台默认大目录为 `/home/boen/Desktop/0927_demo/demo1_0929/拧灯泡plus`，刷新后选择一级双手子任务或 `*.v21glove.h5` 采集文件；不会自动导出。两手保留各自设备身份与真实时间轴。

也可展开高级入口输入录制目录或文件的本机绝对路径。路径指运行本机后端的电脑，不是另一台电脑的浏览器文件系统。服务只监听本机。

正常的录制元数据应说明 hand、device_id、21 路接线、角度单位和角度约定。若旧格式缺字段，可使用导入页的补充元数据 JSON 明确补齐；不能覆盖录制中已知的值，也不能通过手填伪造板端已应用标定。典型补充字段见数据格式文档。

导入失败时先处理身份、接线或原始角语义问题，不要通过换成另一设备的标定绕过检查。原始接线必须完整记录21个不重复的物理CS；原始通道顺序可以与所选手侧的解剖顺序不同，标定和预览按CS映射，不靠同名J通道猜测。

### 对齐 HDF5：手动导入左右手参数

在“选择原始子任务”页展开“对齐 HDF5 手动参数导入”，路径默认指向 `aligned_60hz_exo_glove`。可填写唯一包含 `*.aligned_60hz.h5` 的目录，或指定文件。

1. 分别上传左右手**完整项目标定 JSON**，含各自设备身份、CS、零位、方向及完整采集组。两侧设备必须不同，不接受含 `recording_correction` 的录制修正快照。
2. 两侧分别明确选择角度约定，不根据数值范围自动猜测。若为“已校准有符号角”，上传的必须是**采集时实际已应用的零位和方向**，用于先恢复原始绝对角；不要用新调出的零位替代。后续目标零位在微调区修改。
3. 点击“手动导入对齐 HDF5（双手）”，存在与本次源文件、身份及归一化角度严格匹配的保存快照时，优先恢复最近保存的零位、方向和局部区间；否则优先使用同手侧、同设备的已保存标定作为目标基线，无匹配设备标定时才使用上传参数。建立草稿时仍严格校验CS接线，不匹配会拒绝加载，不借用其他设备参数。采集角反算始终只使用上传的采集参数，不把微调后的目标参数再次用于反算。身份、CS和采集标定标为用户提供，不宣称是文件内嵌证据。
4. 同目录的左右 MP4 通过报告、CSV和逐帧时间核验后，直接参与公共时间轴回放，不重新编码。缺少参数或来源冲突会明确报错，不自动创建标定或跳过坏视频。
5. 导入和微调不改源文件、不写设备标定、不提交处理任务；由用户自行点击保存或正式导出。刷新页面后需重新上传参数。

### 已有标定：录制级零位微调

已有完整标定时，使用“录制级零位微调”，不必重做六步采零。每行 `+1 / −1` 按钮切换该关节全局编码器方向并立即更新预览。显式点击“保存并覆盖原标定”会把全局有效零位和方向写回设备标定；仅本次录制需要的局部区间仍保留在录制快照中。直接导出只保存快照，不覆盖设备标定。

1. 在默认大目录中选择子任务或双手采集 HDF5 并导入；也可用 `?recording=录制绝对路径` 直接打开。唯一左右候选属于同一 `recording_uuid` 时一起导入；手侧、设备、来源分别校验，不按目录名猜。双手 HDF5 的会话身份从头信息确定性派生，明确标为派生身份。只有单手的录制仍可单独使用。
2. 导入后先显示五阶段准备进度：读取录制、校验视频索引、缓冲并验证视频、加载双手模型、对齐公共时间。进度只统计实际完成阶段，不是假下载百分比。导入前更新设备标定列表，默认基线优先级为：来源匹配的最近保存修正、唯一匹配的设备标定、上传或录制内嵌的采集标定。显式选择其他基线仍然有效。所有显示视频可解码、URDF加载完成并对齐到共同有效起点后，才开放微调、时间轴、播放、保存与导出；失败保持锁定，可明确重试。两侧草稿基线独立冻结，导入不写设备标定。
3. **只用一条公共秒进度条和一组播放按钮**，同时驱动左右URDF及全部视频。按每侧自己的时间戳选帧，不共用帧号；公共轴以各手编码器首帧为相对0秒，不是跨设备硬同步。越出某侧录制范围时显示无帧，不用该侧末帧冒充当前。
4. 正常模式下滑条修改本侧全局零位，范围±180°、步长0.1°，也可输入有限数值。遇到编码器零位跳变，点击“选择新的修正区间”，在公共进度条依次点击起终点，或填写本侧起终帧；UI终帧包含在内。此时21滑条只修改所选区间的局部增量。点击“应用区间并返回回放”后恢复拖动和播放并保留标记，可继续修下一段；重叠部分以后一次应用的局部值覆盖，不累加。未应用区间必须应用或取消后才能换手、换录制、保存或导出。
   方向按钮作用于本手全部帧，左右独立，点击可反向；“归零”和全部增量复位只重置零位，不改变方向。局部区间编辑时方向按钮禁用，需先应用或取消区间，再回普通模式修改方向。切换方向不改原始角，也不改变采集时用于反算原始角的参数。
5. 微调区只显示4路视频：左右Data glove各1路，以及头部RGB_left、RGB_right；不显示IR或外置腕部双目。视频采用两列布局，每路窗口按其源分辨率保持长宽比，不统一强制16:9；窄窗口下视频区域换行，手机宽度改为单列，不以固定限高裁切。手套视频保留相对各自编码器首帧的真实偏移，头部RGB保留原设备共同起点，不因隐藏IR重新归零。全部画面共用微调时间轴，缺失来源明确提示，不用其他相机替代。
6. 点击“保存并覆盖两侧原标定”，将全局有效零位及方向分别写入 `config/dataglove/v21/zero/left_<设备id>.json` 和 `right_<设备id>.json`，不存在时创建；不会改写采集 HDF5 的内嵌标定。标准J通过物理CS映射，零位按360°环绕，方向保存目标绝对值；重复保存不累计增量或重复反向。通用标定移除录制专属 `recording_correction`，局部区间只随完整快照保存在 `data/corrections/`。覆盖会影响以后加载该设备标定的录制，不修改原始采集数据。也可直接点击“一键正式导出双手全部帧”，仅自动保存完整快照；没有变化的已保存侧直接复用。
   保存成功后，“建立草稿时使用的基线”切换到最近保存的修正；重新建立、刷新后重新导入同一录制都恢复该快照，不重复叠加零位或反向。快照按真实保存时间选最新，不按随机文件名。需要从头开始时显式选择原始上传参数或设备标定再建立草稿。局部区间仅从快照恢复，不在设备全局标定中。重新导入已校准录制仍须上传采集时的原参数，不能把覆盖后的目标标定误当采集参数。
   新任务沿用设备标定时，全局增量从0开始，但基础零位及方向已经是保存后的值；“本录制草稿尚未保存（已加载所选基线）”仅表示尚未保存这个新录制的修正快照，不表示设备标定未保存。其他录制的局部区间不会带入新任务。
7. 自动保存全部成功、两侧参数校验通过后才提交联合任务；任意一侧保存失败都不排队。保存期间继续调整不会改变本次点击冻结的参数；录制或基线切换则不提交旧草稿。任务处理各自完整序列，全部成功才发布联合结果：目录录制写根目录 `processed.h5`，单文件采集或对齐录制写同目录 `<源文件stem>.processed.h5`。两侧包含三阶段输出及独立真实时间轴；已有同一录制结果仅在新处理完整成功后原子替换。
   导出按钮旁可勾选“Wuji Hand2 自碰撞”，默认不勾选以保持快速导出；勾选后较慢，未勾选可能穿模。微调单/双手和“单手处理与导出”均支持。选项在点击导出时固定，保存快照期间或之后改变勾选不影响本次任务；队列卡显示实际提交状态。该选项仅处理各手自身Hand2碰撞，不包含双手互碰或环境碰撞。
8. “全局导出队列”标签页显示运行、排队、完成和失败任务。提交后可切回微调继续编辑、导入另一个子任务；切换模块、录制或刷新页面不会清空服务内队列。可移除排队项、确认停止并移除运行项；移除完成项不删除已有结果。服务重启会清空内存队列，不会自动重提任务。

连续播放使用浏览器原生视频播放，并校正漂移；URDF每侧只保留一个在途计算和最新目标，不排队补放过期帧。任一路视频等待缓冲、定位或失去同步，或模型预览落后时，冻结公共时间并暂停全部视频；当前帧对齐且缓冲就绪后，重设墙钟起点继续，不追赶等待期间的时间。拖帧或修改增量会取消过期请求；模型下方标注实际显示帧。暂停和单帧定位要求目标帧准确，连续播放按软件容差判断，不能视为曝光级硬同步。视频下方使用浏览器呈现回调标注实际画面帧，不支持时明确标为媒体时间估计。范围外隐藏画面，不冻结末帧。
同步保护立即生效，但短于350毫秒的等待不显示提示；持续等待时在时间轴固定位置显示小字，连续恢复500毫秒后收起，避免短暂等待反复闪烁或推动画面布局。手动暂停、切换录制时立即清除提示。

多路高清视频首次准备包含完整性核验和浏览器解码探测，微调区必须等全部显示来源就绪，不能让模型提前开始共同回放。真实不存在且无校验错误的可选视频会明确标为缺失；损坏来源不能当作缺失而跳过。浏览器不是硬实时系统，慢设备或慢预览会降低共同回放速度，原始数据和正式导出帧不减少。模型仅在可见且姿态/视角发生变化时绘制，切回模块显示当前姿态。结果只读回放保持独立的加载行为。

微调只改变对应物理通道的零位，不自动修改方向、比例、接线或关节定义；如果实际问题是这些参数，应先纠正对应配置，而不是用零位补偿掩盖。

## 2. Web 六步标定

离线模式从已经打开的录制选窗，不要求手套在线；实时模式按上面的流程采集点击后的新窗口。两种模式共用同一套六组标定、方向编辑和模型预览。

六步顺序为：大拇指、食指、中指、无名指、小拇指、小拇指 CMC。

1. 找到对应手指确实处于模型零位的片段。摊平手掌，四指伸直并拢；拇指按模型显示的外展姿态摆放，不能拿任意静止握拳作为零位。
2. 用开始帧、结束帧选择窗口。区间是 `[开始帧, 结束帧)`，结束帧不包含；帧号从 0 开始。推荐窗口约 1.5 秒。
3. 确认姿态后采集该组。程序验证窗口长度、连续性和稳定度，以环形中位数计算零位；失败不会覆盖已有组的结果。
4. 六组可以来自不同时间区间。完成后通过已知动作片段检查各通道方向；方向只能为 `+1/-1`，更改后观察模型。
5. 点击保存。正式文件只在六组完整且参数有效时保存。

没有零位姿态的录制不能凭空生成正确零位。应使用与本次录制适用的独立标定；重新安装、磁钢移动、维修或影响参考姿态的佩戴变化后，设备 ID 相同也不代表旧零位仍然适用。

### 保存与覆盖

固定目录是项目内 `config/dataglove/v21/zero/`，文件名为 `left_<手套id>.json` 或 `right_<手套id>.json`。由后端直接写入，不依赖浏览器下载目录，不调用原网关，不写板端标定。

同名文件默认拒绝覆盖；确认覆盖后才原子替换。已经导出的结果内嵌旧标定快照，因此之后重新标定不会改变历史结果的来源信息。

## 3. 离线处理

选择与录制手侧、设备 ID、接线一致的完整标定，开始处理。

处理器从初始状态按原始帧顺序求解全部数据。不将预览拖动状态带入正式导出，不按视频帧率抽稀，不自行重采样或插值。任务进度显示的是已经处理的编码器帧数。

双手目录录制写入任务根目录唯一的 `processed.h5`；双手采集文件写入同目录 `<源文件stem>.processed.h5`；单手模式仍在 `data/processed/` 新建文件。每侧包含三阶段输出、时间戳、有效状态和错误原因。完成不意味着每帧都有效；任务异常或取消时不发布 `.part`，保留此前完整的正式文件。每个任务独立进程、FIFO单并发，停止当前任务后会继续下一项。

也可使用命令行：

```bash
pixi run inspect --recording /绝对路径/录制目录
pixi run process --recording /绝对路径/录制目录
```

对双手采集文件，单侧命令加 `--hand left` 或 `--hand right`。`process` 优先使用显式/本地匹配标定，缺少本地文件时可用已核验的内嵌标定；双手同文件导出使用 Web 微调模块。

`process` 默认按录制身份从固定目录选择标定，可通过 `--calibration /路径/标定.json` 明确指定，只读加载。`--metadata /路径/补充.json` 用于补齐缺失事实。`--output` 若指定，必须位于本项目 `data/processed/` 内且目标不存在。

### 已处理结果的 Wuji Hand2 自碰撞后处理

已有本工具生成的单手或双手 HDF5（包括微调后以无碰撞模式导出的文件），可在 Web“全局导出队列”中的“已有结果补做自碰撞”填写文件绝对路径，点击“补做自碰撞并另存”。已完成的无碰撞任务卡也提供“补做自碰撞（另存）”快捷按钮。无需重新上传标定或打开原始录制；原结果保留，进度及新文件均显示在队列中。

也可通过以下接口提交；每次请求处理一份文件，多份请求进入同一个全局 FIFO 队列：

```bash
curl -sS http://127.0.0.1:8091/api/jobs/wujihand2-collision \
  -H 'Content-Type: application/json' \
  --data '{"path":"/home/boen/Desktop/0927_demo/倒酒插花挂衣服/倒酒插花挂衣服_hand_processed.h5"}'
```

接口返回标准任务信息，`kind` 为 `wujihand2_collision`。通过 `GET /api/jobs/{id}` 查询进度，或在 Web“全局导出队列”查看、停止、打开结果。`DELETE /api/jobs/{id}` 沿用现有取消语义。

- 原 HDF5 只读，结果在同目录另存为 `{原文件stem}_wujihand2_collision_{uuid}.h5`，不覆盖已有文件。
- 直接读取已有 `hand/keypoints_m`，按每侧原顺序重跑启用自碰撞约束的官方 Hand2 IK；不重算外骨骼或人手骨架，不需要原始录制及外部标定文件。相机回放仍需要原视频来源。
- 时间戳、帧数、外骨骼、人手关键点、录制及标定快照保持不变，仅更新 `wujihand2` 和相应处理追溯/有效帧计数。单手、双手均支持，但源文件必须完整、关键点顺序受支持、模型资产指纹匹配。
- 自碰撞约束仅对此任务在内存中启用，普通快速导出配置不变。这是各手自身的碰撞处理，不包含左右手之间或与环境/物体之间的碰撞。
- 无效人手帧、非有限输入或无法满足约束的帧保留原时间戳，写入 `NaN / valid=false / error`；不沿用旧的无约束 Hand2 值冒充成功，也不插帧、丢帧或补造结果。任务完成不代表所有帧有效。
- 入队时记录源文件 SHA256，执行时校验私有快照；源在排队期间变化则拒绝处理。全部手侧处理完成后才原子发布，取消或异常不发布半成品。
- 各侧 `metadata/processing_json` 的 `wujihand2_postprocess` 保存源路径/摘要、实际参数、当前实现和模型指纹；原上游追溯保留，当前 `wujihand2_self_collision` 标明已启用策略。

Python 批处理入口 `glove_calibrate.collision_processing.process_hand2` 可通过 `self_collision=False` 先生成无碰撞约束版本，再对该结果以 `self_collision=True` 重算碰撞版。两步均应显式传入相同的 `pinch_position_weights`，例如五指各为 `0.8`。这是将指尖位置项倍率从默认 `1.0` 降到 `0.8`，不是把吸附混合上限 α 从 `0.7` 提到 `0.8`；方向项、全手形状项和 α 规则保持不变。参数只作用于本次调用并写入结果追溯，不修改全局配置。HTTP 碰撞接口仍沿用正式配置的默认位置倍率。

## 4. 同步回放

从结果列表打开文件，或输入另一个本工具处理结果的绝对路径。模型资产必须与文件记录的指纹一致；否则明确报错，不套用错误模型。

联合结果同时显示左右手，每侧分别显示 V21 外骨骼、人手骨架、Wuji Hand2 和本侧 dataglove 相机。只用一组播放/暂停、倍速、前后时间点、拖动与秒数定位控件；公共秒轴合并两侧真实时间戳，各侧独立选帧，短侧结束后隐藏该侧模型与视频而非冻结末帧。单手旧结果只显示存在的一侧；视角及数值区按手侧独立。

连续回放不会因模型帧请求较慢而停止视频或公共时钟；待显示目标采用最新值，暂停/拖动后精确读取最终目标。下一有效帧读取期间保留上一有效模型，遇到明确无效帧或真实读取错误仍隐藏，不将保留姿态标作新帧。

回放只读已保存结果，不再运行标定或 IK。失效阶段隐藏姿态并显示原因，不把上一帧冒充当前帧；其他有效阶段仍然可看。两种模型使用各自定义的根坐标，人手骨架为文件注明的局部坐标，三栏并排不代表它们已经对齐到同一个世界坐标。

人手拇指掌骨附近的CMC点在拟合后重建为腕点与MCP的中点，去掉向外再折回的形状；其他20点不变。网页显示完整21点，按照MediaPipe编号及标准连线绘制，数值面板、导出和Hand2重定向使用同一套坐标。补回的CMC属于几何估计，不是MediaPipe检测。旧结果不自动改点，应重新处理并打开新文件。

新处理默认关闭Hand2自碰撞优化，以减少导出耗时；仍求解Hand2关节，但结果可能穿模。可在Web导出前勾选自碰撞选项，无需修改配置文件。结果信息显示实际策略，刷新页面不改变已有HDF5；再次导出使用新任务选项，已排队或运行的求解器不随勾选变化切换。启用时才应用对应间隙与最终校验，详见数据格式文档；任何模式都不提供外部环境或帧间运动安全保证。

### 左右手 dataglove 相机

结果页相机专指各侧 `dataglove/video.h264`，不是外置双目腕相机。根据所选侧 `metadata/recording_json.path` 关联原录制，核对手侧、设备、录制身份、来源哈希及编码器时间轴；不复制视频进HDF5，原始来源文件需仍可读取。

两路glove视频跟随结果公共时间轴，保留各自相对编码器首帧的真实起止偏移，不将视频首帧重置为0；跨手仅按各自编码器首帧相对对照，不承诺硬件精确同步。无对应视频帧时隐藏画面，来源缺失或冲突明确提示，不阻塞模型回放，也不替换成其他相机。

可以通过 `/?result=结果文件路径` 直接打开结果。联合文件不再切换手侧，而是同时显示两侧；下载始终获取整份联合文件。回放只读已有结果，无需重新导出。

## 常见问题

- **只有调试设备，没有实时角**：DGST模式先启用板端采集再连接；若相机探测失败，可改选“仅编码器兼容”直接连接，不需修相机才能看角度。若接口被其他程序占用，先确认对方没有录制，再由操作者释放；本工具不会强制杀掉其他进程。
- **录制中断**：保留 `.partial` 文件排查原因，不能重命名冒充完整录制；重新连接后重新采集。
- **采样不连续/手指不稳定**：重新选择符合姿态要求的完整静止窗口；不要把丢帧编号补成连续或用滤波掩盖采样问题。
- **已标定角缺原标定**：必须找到录制时对应的板端标定，当前另一份零位不能用于恢复。
- **关节方向反了**：在标定页结合明确动作修正该通道方向，再保存和重新处理。
- **机构无解**：检查零位、方向、接线以及数据本身。失败帧会保留时间位置并标无效。
- **模型显示异常但数值可读**：检查浏览器 WebGL；模型资源本地加载，不需要外部 CDN。
- **服务重启后录制/结果未打开**：重新打开文件。内存任务编号不是持久化的录制身份，正式结果和已保存标定仍在磁盘上。
