# V2.1 外骨骼个性化骨长标定流程与解算设计

日期：2026-10-12。状态：调研与设计，未实施生产算法；所有建议阈值均待实物试采确认。

## 1. 结论与范围

目标：外侧佩戴的 21DoF 外骨骼观测 → 个性化人体运动学参数 → 固定尺寸的实时人体 IK → MediaPipe 顺序的 21 个三维点。不是把机械关节中心改名成人体关节，也不是机器人手重定向。

本轮交付重点是可操作的**骨长标定流程**。不修改已有采集、标定、骨架拟合、显示或导出算法；不连接设备执行动作，不安装研究库，不训练网络。

推荐路线：**独立尺寸测量 + 分动作多帧采集 + 分阶段有界非线性最小二乘 + 独立动作验收**。人体骨长、设备机械尺寸、每次佩戴偏移分层保存；实时阶段只求姿态，不逐帧改变骨长。

必须先接受的边界：

1. 此处“骨长”主要指**有效运动学骨段长度**：人体关节中心到关节中心，以及末端关节中心到指定表面指尖点。它不等于医学影像里的骨组织长度。皮肤关节纹、触诊标记仅是带误差的代理测量。
2. 五指末端的 6DoF **数据维度**，不代表 30 个独立自由度。若位姿由同一组编码器 FK 计算，不能与这些编码器观测按独立噪声重复计权。
3. 末节长度与安装偏移存在严格等价解；仅多采末端位姿不能保证唯一辨识。
4. 骨长固定不等于掌部所有点固定。若模型包含无名指/小指掌弓运动，MCP 可以沿固定长度的掌骨链运动，但不能通过随帧改 root 参数模拟。
5. MediaPipe 仅规定输出编号和语义，不提供本硬件的标定真值；不运行其视觉模型。

## 2. 当前硬件与代码事实

### 2.1 URDF 和观测链

只读解析左右 URDF，并运行当前 MuJoCo 模型，得到两侧均为：根 link `wrist_link`，22 links、21 个转动关节。

| 指链 | URDF 关节顺序 | 当前末端刚体 | 当前虚拟指尖 |
|---|---|---|---|
| 拇指 | CMC flex → CMC abd → MCP → IP | `thumb_ip_link` | 末端轴锚点外延 30 mm |
| 食指 | MCP abd → MCP flex → PIP → DIP | `index_dip_link` | 末端轴锚点外延 25 mm |
| 中指 | MCP abd → MCP flex → PIP → DIP | `middle_dip_link` | 同上 |
| 无名指 | MCP abd → MCP flex → PIP → DIP | `ring_dip_link` | 同上 |
| 小指 | CMC → MCP abd → MCP flex → PIP → DIP | `pinky_dip_link` | 同上 |

依据：`core/dataglove_skeleton.py:12–59,68–74,133–168,176–203`。四指虚拟末端使用刚体局部 +Z，拇指方向由零位末两机械轴锚点连线建立。这些 25/30 mm 是代码常量，不是人体测量。

右手零位示例：食指两个 MCP 机械轴中心分别为 `(-7,24,65)` 与 `(9.5,24,65)` mm，相距 16.5 mm。因此不能把两个外骨骼 MCP 轴等同于人体同一关节的两根转轴。拇指前两个机械轴中心也有明显空间分离。

当前标准 J 定义见 `joint_channels.py:14–35`：J1–5 侧摆，J6–10 掌骨屈伸，J11–15 拇指 MCP / 其余 PIP，J16–20 拇指 IP / 其余 DIP，J21 小指 CMC。它们是通道语义，不是已经校准的人体角。

### 2.2 实际接入的数据，不等于尚未提供的 SDK 能力

- `usb/usb_stream.py:27–33,386–394`：`EncoderFrame` 只含序号、时间、21 路角、接收时间、流 ID；编码器 payload 为 2 字节通道数 + 21 个 float64，共 170 字节。
- `recordings.py:17–34` 与 `docs/data-format.md:7–27`：统一 `Recording` 保存 `N×21 angles_deg`，没有五指 `position/quaternion` 字段。
- 本轮查阅的一份现有录制 `sensors.json` 声明 MA782、21 通道、100 Hz delivered_scan，时间为板端 `CLOCK_MONOTONIC` 扫描中点；另有 IMX415 H264 视频。帧样本仅有角度等字段，没有五指位姿。
- `usb/dgst_protocol.py:163,199–247` 校验上述编码器/视频协议；不能据此推断其他 SDK 或硬件没有末端 6DoF。
- 当前模型加载及 FK 已能提供每根指链末端机械刚体的位置和旋转；现有人手适配器只提取位置点/虚拟指尖，没有把末端旋转作为独立残差输入。

**待确认的是 6DoF 的来源、参考坐标系、末端坐标系定义及精度，不是否相信设备能提供它。** 新 SDK 的样本、字段定义尚未在当前项目中找到。设计必须支持以下分支：

| 位姿来源 | 可以做什么 | 不能声称什么 |
|---|---|---|
| A：独立位置/姿态测量 | 在完成时间、外参和噪声标定后，与编码器联合估计 | 没有装配标定就把传感器原点当人体指尖 |
| B：编码器 + URDF FK | 作为机械几何预测，配合人体测量和接触约束做标定 | 把派生 30 维位姿当新增 30 维独立信息 |
| C：SDK 已求出的人手骨架 | 作为外部比较结果，保留其算法/标定来源 | 把已解算骨架冒充原始末端观测，形成循环验证 |

### 2.3 现有标定不是骨长标定

`calibration.py:18–24,141–200` 的六组标定采集各通道静止零位和方向，检查中央 80% 的角度运动不超过 1.5°。它没有估计掌宽、MCP 位置、各骨段长度或安装外参。

`core/encoder_kinematics.py` 对 PIP/DIP 及拇指 IP 使用四连杆变换。`config/dataglove/v21/{left,right}.json` 明确有参数沿用上一版、待结构确认；右手 `ready=true`，左手 `ready=false` 且方向未完整实物验收。右拇指 CMC flex 的机械比例为 0.9，左侧为 1.0。不能把这些转换后的机械角当成人体角真值。

原有骨架路径：`JointRetargetPipeline` → `GloveLandmarkAdapter.to_mediapipe()` 取每指最后三个机械轴锚点和虚拟指尖 → `ManoMorphologyFitter.fit()` 使用固定手型拟合末端及方向 → `Engine.step()` 把 CMC 改为腕点和 MCP 中点。

- `core/mano_morphology.py:414–458` 还包含捏合间距压缩；它不能作为新标定的观测来源或验收真值。
- `engine.py:216–218` 的 CMC 中点补偿必须在新人体模型正式切换时移除，不能迁入新标定器。
- `web/src/scene.js:274–309` 只画收到的点；当前显示、导出和 Hand2 输入使用补偿后的同一份坐标，拟合器内部骨架则不同。

## 3. 先分清三个标定层级

| 层级 | 参数归属 | 什么时候更新 | 禁止混用 |
|---|---|---|---|
| 设备机械标定 | 物理 CS、编码器角语义、零位/增益、四连杆几何、末端机械 frame、设备噪声 | 设备装配/维修/结构调整后 | 不用人体骨长补机械连杆或零位错误 |
| 用户手型标定 | 解剖根点、有效骨段长度、掌部形态、个人 ROM/耦合先验 | 首次使用；生长或明确尺寸变化后 | 不因重新佩戴而随意改变骨长 |
| 本次佩戴标定 | 腕座到人体掌坐标外参、五指安装外参、接触面偏移及可解释的小幅角偏差 | 每次穿戴、滑移或重新固定后 | 不把安装漂移写回永久手型 |

现有设备零位逻辑可以保留，但必须建立单独的人体 profile；不复用 `zero_offsets_deg` 存储人体骨长。每个参数保存 `measured / estimated / prior_fixed`、单位、来源、不确定度和允许更新层级。

## 4. 可执行的操作流程

下面时长和次数是**本项目试采建议**，不是 MANUS 的内部算法或精度承诺。所有动作在舒适范围内缓慢执行，禁止外力掰到极限；有疼痛或机械干涉立即停止。校准顺序对左右手分别执行，不能假设同尺寸或同 CS 接线。

### 步骤 0：设备与数据准入

1. 记录设备、手侧、固件、URDF/机构配置哈希、物理 CS 排列、编码器角语义。
2. 确认五指末端 6DoF 属于来源 A/B/C，保存原始样本与 SDK 文档。明确位置单位、四元数顺序、主动/被动旋转、变换方向、参考 frame、时间戳及有效位。
3. 若来源 B，先完成机械几何核验；至少抽查伸展/中度弯曲/屈曲三处的机械末端位置与旋转。当前左手未完成的方向验收不能由人体优化器掩盖。
4. 单指、单关节小幅动作，核对通道方向、串扰和实际机械耦合；记为设备/映射证据，不预设人体角与机械角 1:1。
5. 静止采集 3–5 秒，统计角度、末端位置/姿态噪声以及时间间隔、缺帧。若位姿是 FK，噪声须从编码器与模型不确定度传播，不能宣称独立测得。

**通过条件**：数据来源和坐标已知、无手侧/列序/单位歧义；否则允许采原始数据，但不发布骨长标定结果。

### 步骤 1：不佩戴时的简单测量

使用软尺、直尺或卡尺；有条件配带比例尺的掌面和侧面照片，人工标记，不依赖 MediaPipe。建议每项量三次，记录均值与重复性，不只输入一个数字。

| 测量 | 用途 | 重要限制 |
|---|---|---|
| 腕参考点到中指 MCP 的掌部长度，食指到小指 MCP 横向跨度 | 尺度和掌部初始化 | 采用可复现的标记定义；不是任意腕纹到指尖总长 |
| 食/中/无名/小指 MCP→PIP、PIP→DIP、DIP→指定表面指尖 | 12 段有效长度的测量先验 | 掌纹/皮肤纹不等于骨关节中心；保留代理误差 |
| 拇指 CMC→MCP、MCP→IP、IP→表面指尖 | 3 段拇指有效长度 | CMC 触诊困难，可先用弱先验；不可用腕→MCP 中点替代 |
| 五指远节厚度、接触指腹位置 | 安装法向偏移与捏合表面模型 | 轻触，不挤压皮肤；避免用指尖点重合代替指腹接触 |
| 各指总有效长度及掌宽复测 | 交叉校验分段与整体尺度 | 不与上面的相关尺寸重复当成独立高精度测量 |

如果只能提供少量尺寸，优先测掌部尺度、每指总有效长度、末段有效长度以及末端安装轴向偏移。近/中节先按人体比例带不确定度初始化，后续在数据支持时再释放；**不得声称已独立识别所有骨节**。

尺寸只能作为先验时，如实显示“先验固定/先验主导”。要达到真实内部骨中心的毫米级精度，需要更高质量的测量依据，不是增加优化迭代次数。

### 步骤 2：佩戴与末端安装偏移测量

1. 固定腕座和各远端连接件，拍摄或记录安装位置；不得要求机械轴必须与人体轴完全重合。
2. 对五指明确远端安装 frame：可为末端刚体原点或传感器原点。记录它到实际指定指尖的轴向距离，能量到的侧向/背侧偏移和远节厚度一并记录。
3. 用多个缓慢姿态检查连接件相对远节是否滑动。固定刚体偏移模型不成立时应调整佩戴；不要开放每帧偏移去吞掉滑移。
4. 若硬件实际上连接到指套表面而非远节刚体，给安装残差更宽的不确定度，并保存该建模限制。

**关键约束**：末段长度和安装轴向偏移至少一项必须有独立测量/固定依据。若两项都只有宽先验，输出它们的相关性并禁止“精确骨长”认证。

### 步骤 3：建立腕/掌参考系和中性姿态

- 人体掌 frame H 的原点采用书面定义的腕参考点（例如两侧腕标记中点）；纵轴沿掌部参考方向，横向朝食指侧，第三轴按右手系叉乘。
- 该 Wrist 是工程中可复现的解剖代理，不保证与视觉模型隐式标注完全相同，也不等于 URDF `wrist_link` 原点。
- 记录自然放松位、舒适伸展位各 3 秒、重复 3 次；用实际角度/标记测量建立软参考，不把每个姿态都强制设成全部关节零度。
- 如末端位姿参考系固定在腕座，标定固定 `T_EH`；如参考系是外部世界且手腕会动，必须提供腕位姿或把每帧腕姿态作为显式未知量，不能继续假设固定 `T_EH`。
- 无法建立绝对世界参考时，只承诺局部掌坐标骨架。

### 步骤 4：四指分解运动采集

每指执行 3 个慢速往返周期，每周期约 3–5 秒；优先选独立动作而非长时间重复同一姿态。

1. **伸展到自然屈曲**：覆盖总体活动范围，建立机械观测与人体姿态的初值。
2. **MCP 主导屈伸/桌面手形**：尽量保持 PIP/DIP 较直，帮助区分掌根、近节长度与 MCP 偏差。
3. **钩形屈曲**：MCP 尽量保持较伸展，主要改变 PIP/DIP，增加中/末节的激励差异。
4. **舒适开指—并指**：在伸展和轻屈两档执行，辨识 MCP 外展及其随屈曲变化的范围。
5. **小指掌弓运动**：轻度杯状手形，检查 J21 与小指根运动的关系；无名指掌弓没有直接对应传感器，不能假定直接可测。

不要求 PIP 与 DIP 完全独立——生理耦合做不到的动作不能作为强制验收。若动作仍不能区分某两个长度/角参数，则保留测量先验，不用更强耦合项“制造可辨识性”。

### 步骤 5：拇指专用采集

分开采集 CMC 掌内/掌外方向的运动、MCP 屈伸、IP 屈伸以及自然对掌。各做 3 个舒适慢速往返。拇指不使用四指的平面 PIP/DIP 模型。

重点检查：CMC 相对掌部的位置是否稳定合理；对掌方向是否由人体模型产生；IP 是否因末端拟合而被锁死或出现反向补偿。不能借 CMC 点随姿态任意平移来拟合。

### 步骤 6：四组轻捏合与已知几何接触

- 拇指分别与食/中/无名/小指轻触；每组保持约 3 秒、重复 3 次，包含完整的接近—接触—分离过程。
- 接触窗口由操作提示、按键或独立观察标记；不能仅凭待拟合指尖距离小就反推“发生接触”，否则循环论证。
- 接触的是指腹表面，不是两个骨端中心。使用带厚度/半径或已定义接触点的模型，不强制 MediaPipe tip 两点恒为零距离。
- 推荐补一组已知厚度量块或已知尺寸物体的轻夹持，用独立尺寸补充绝对几何约束。物体尺寸和接触面有测量误差，必须进入权重；未知物体位姿可估计，但不能同时把其尺寸任意调整。
- 可选：指尖接触已知平面/标记位置；只有该平面或标记在参考坐标系中的位置已知，才可作为绝对位置约束。

接触帧用于标定几何关系，不在实时阶段常开“指尖吸附”。非接触帧应保持真实间隙。

### 步骤 7：回到起始姿态，检查佩戴滑移

重新采集步骤 3 的姿态与一组轻捏合。若残差相对起始明显系统性改变（建议先用静止噪声的 3 倍作提示阈值），检查连接件滑移、绑带变化和编码器漂移。确认滑移则重新佩戴/重新采集；不要通过改变骨长让前后都勉强通过。

### 步骤 8：离线分阶段求解与结果审查

按第 7 节执行，不一次放开所有骨长、根点、转轴、偏移、角映射。输出每项尺寸的估计值、来源、置信区间/重复性、是否撞到边界、是否先验主导，以及每种动作的残差。

候选结果必须满足：固定骨段几何、人体姿态范围、安装偏移可解释、不同初始化结果稳定。只满足 `solver.success=True` 不算通过。

### 步骤 9：独立动作验收并冻结 profile

另录一段未参与求解的验证数据，改变动作顺序与速度，包括连续屈伸、钩形、张合、四组捏合和非接触接近；有条件加入不同尺寸物体。不能把同一动作的邻近帧随机分成训练/验证来冒充独立验证。

通过第 9 节指标后发布只读个性化参数；失败则按残差类型返回对应步骤。每次重新佩戴优先仅重估安装参数，只有独立尺寸证据支持才允许更新人体骨长。

## 5. 参数、坐标和输入输出契约

### 5.1 坐标约定

统一 `T_AB` 表示“把 B frame 的列向量变到 A frame”，长度 m、角度 rad、时间 int64 ns；JSON/磁盘可保存 quaternion `xyzw`，导入必须显式转换，不猜 SDK 排列。

- E：末端观测的参考 frame，可为腕座或已明确的测量基座。
- H：人体腕/掌 frame。
- D_f：人体远节刚体 frame，原点在 DIP；拇指为 IP。
- F_f：定义明确的表面指尖 frame，方向继承远节刚体约定。
- S_f：传感器或末端机械安装 frame。

预测观测：

`T_ES[f,t] = T_EH[t] · T_HD[f](q_t, g) · T_DF[f](g) · T_FS[f](x_f)`。

其中 g 是固定人体几何，x_f 是本次佩戴固定安装外参。若 E 随腕座刚性运动，`T_EH[t]` 为会话常量；否则使用独立腕测量或每帧显式求解。

SDK 若输出末端 link L 的位姿，还需经已知 `T_LS` 转换。当前虚拟指尖常量不是 `T_LS` 的独立标定依据。

左右手分别维护实物接线与外参；两侧都必须使用 proper rotation（det=+1）。不能把位置镜像 `S p` 的做法直接用于四元数；涉及规范镜像时旋转应按一致的两侧基变换推导，例如 `S R S⁻¹`，不能使用 det=-1 的单侧反射矩阵冒充旋转。

### 5.2 人体骨架参数

推荐显式低维人体运动学，不把整个外骨骼 URDF 当人体模型：

| 参数块 | 形状/维数 | 默认处理 |
|---|---|---|
| 四指近/中/末段 + 拇指掌骨/近/末段 | `(5,3)`，15 个长度 | 个体固定；测量与数据共同约束 |
| 四指静止 MCP 根点 + 拇指 CMC 根点 | `(5,3)`，15 个坐标 | 以人体掌 frame、测量和低维掌形先验约束 |
| 掌部整体尺寸 | 掌长/掌宽等派生量 | 与根点一致，不再作为完全自由的重复参数 |
| 关节局部基、轴、掌弓中心 | 拓扑定义中的固定量 | 先采用人体先验并固定；不可同时全量拟合自由轴与根点 |
| 腕座—人体掌外参 | SE(3)，6 个局部参数 | 固定于本次佩戴；独立标记/参考姿态约束 |
| 五指 F→S 安装外参 | `5×SE(3)`，30 个局部参数 | 各项可测则测；逐块释放，保留轴向规范 |
| 机械观测映射 | m 路各增益/截距，最多 2m 参数；少量已知同指耦合项 | m≤21；缺测掩码；不拟合自由 21×21 矩阵 |

前两块共 30 个几何候选参数，不代表它们都能自由辨识。初始固定轴系时，含腕外参与末端安装的全局候选参数为 `66 + 2m + c`，c 是明确启用的少量耦合参数；实际优化只包含通过可辨识性检查的子集。固定/派生/待估参数在 profile 中显式分开。若后续需要个体轴偏差，另立参数块、增加独立观测再验证，不能悄悄扩自由度。

姿态建议：四指 MCP 外展/屈曲 + PIP + DIP 共 16；拇指 CMC 两轴 + MCP + IP 共 4；无名指、小指掌弓各 1，共 22 个模型角。人体 22 与设备 21 不要求一一对应。无法观测的掌弓自由度固定或保留强先验，不能假装独立测得。拇指 MCP 外展等额外自由度仅在数据足够时单独扩展，不作为默认自由补偿。

指间耦合是软约束，不用 `DIP = 常数×PIP` 硬锁死所有人。人体限位不是机械 URDF 限位；先用文献/开源模型合理范围，再结合无痛实际动作保守调整。

FK 结构约束：四指从人体 MCP frame 依次执行外展/屈曲旋转、近节平移、PIP 旋转、中节平移、DIP 旋转、末节平移；拇指单独从 CMC frame 执行两轴运动、掌骨平移、MCP 旋转、近节平移、IP 旋转和末节平移。局部单位骨轴及转轴在零姿态定义后固定。22DoF 是本项目设计选择，不是已由硬件验证的解剖真值；CMC 两轴模型是低维近似，需用拇指留出动作验证是否充分。掌弓若启用，MCP 根点由固定掌骨链旋转得到，不直接逐帧优化根点坐标。

### 5.3 输入与输出维度

每帧标准化观测：

- `timestamp_ns`、各源原始时间、时钟归属、同步误差；不只保存插值后的统一时间。
- `encoder_raw_rad[21]`、`encoder_valid[21]`、原始 CS 映射与角度约定；保留原始计数/角度证据。
- `tip_position_m[5,3]`、`tip_quat_xyzw[5,4]` 或等价 `tip_T[5,4,4]`、`tip_valid[5]`。
- `tip_covariance[5,6,6]` 或显式噪声模型；来源 A/B/C、派生依赖 ID、FK/SDK 版本。
- 可选 `wrist_T[4,4]`、腕有效性及协方差；按动作段记录外部接触标签、对象几何与测量先验。

位姿与角度先做时钟注册，再在限定小时间差内匹配；旋转插值用 SO(3)/SLERP，角度先按连续段 unwrap，禁止跨重启/长间断插值。是否需要估计固定时延必须由独立动态数据支持；同一编码器派生的 FK 不提供新的时延观测。多源协方差还需记录跨手指、与腕参考/编码器的相关块，`5×6×6` 对角块本身不足以描述所有相关性。

人体解算输出：`q_rad[22]`（冻结维仍有定义）、`keypoints_m[21,3]`、可选解剖关节 frame `[16,4,4]`（腕 1 + 拇指 3 + 四指各 3）、逐阶段有效性、残差、观测缺失和先验主导标志。MediaPipe 标准没有定义这些关节 frame；它们是项目扩展，不混入关键点顺序。

关键点顺序：0 Wrist；1–4 thumb CMC/MCP/IP/tip；5–8 index MCP/PIP/DIP/tip；9–12 middle；13–16 ring；17–20 pinky。不得给拇指造 PIP/DIP 编号。

## 6. 哪些参数不能只靠动作解出

### 6.1 末段长度—安装轴向偏移的严格歧义

简化位置关系：

`p_S = p_DIP + R_D (L_distal · e + t_FS)`。

任意 δ 都有：`L_distal' = L_distal + δ`、`t_FS' = t_FS − δe`，预测的传感器位置与旋转不变。即使人体各关节角完全已知，更多末端 6DoF 帧也不能打破该等价关系。

需要独立末段长度测量、独立安装轴向距离或可信的独立指尖/接触几何约束。一般的轻捏合若接触位置/软组织厚度也全自由，并不能保证解除歧义。强先验只是选择一个解，不等于测出了该参数。

### 6.2 其他主要歧义

| 歧义 | 症状 | 处理 |
|---|---|---|
| 掌 frame 与全部根点的刚体规范自由度 | 整体旋转/平移变化但预测不变 | 固定解剖参考系，或独立约束腕外参；不能同时让基与所有根自由漂移 |
| 人体零姿态、局部基方向和角映射截距 | 同一姿态被不同零点解释 | 固定姿态定义与局部基，测量/软约束参考姿态，再估计一个层级的残余偏差 |
| 近/中节长度与每帧屈曲角补偿 | 指尖很好，中间关节错误 | 多种解耦动作 + 段长/中间点代理测量；必要时冻结长度比例 |
| 完全伸直附近的近/中节退化 | 长度列近共线，数值不稳定 | 增加不同 MCP/PIP 分布的弯曲动作，不重复堆静止帧 |
| 仅平面屈伸下的外展轴/掌厚/安装旋转 | 面外参数漂移 | 外展、对掌、斜向接触；仍无支撑则固定弱观测维 |
| 可变腕座位姿与指根位置 | 手腕运动被拟合成骨架变化 | 独立腕观测或显式每帧腕未知量；仅输出局部坐标时固定规范 |
| 安装滑移与尺寸变化 | 不同动作段需要不同“骨长” | 同次佩戴前后复测；漂移触发重佩戴，不允许在线改骨长 |
| 同源 FK 与编码器重复信息 | 后验置信度虚高 | 使用联合协方差/生成式编码器模型，或只选择一种统计表示 |

### 6.3 实际可辨识性检查

对数据残差 Jacobian 做**尺度归一化后的 SVD**；分析全局几何参数时，投影或 Schur 消去每帧姿态、外参等 nuisance 自由度，不能只检查固定姿态下的几何 Jacobian。

分别报告：数据项的信息秩、加入独立测量后的秩、加入人体先验后的后验稳定性。不要把正则项让矩阵满秩解释成数据已识别全部骨长。

采用按动作段留一验证、多初值拟合、按动作段 bootstrap 或 profile likelihood 检查区间与相关性。高度相关或置信区间很宽的参数应冻结/补测，并记录来源；不输出小数点后多位掩盖不确定性。

## 7. 分阶段参数辨识及目标函数

### 7.1 辨识顺序

1. **设备层锁定**：先确认 CS/方向/单位/四连杆装配分支；设备参数若不可信，来源 B 的末端 FK 不能当绝对真值。
2. **测量初始化**：由掌部尺寸、分段代理测量和合理比例建立人体几何初值；定义固定零姿态/轴系，冻结弱辨识参数。
3. **坐标与安装初始化**：在几何固定时，结合腕/安装测量及多方向姿态求 `T_EH` 和安装旋转/可辨识平移；保留末节—偏移规范约束。
4. **人体姿态与角映射初始化**：固定几何，按各指分解动作估计每帧 q 与少量机械→人体增益/截距。没有独立角或位置依据的映射参数保留先验。
5. **骨长与根点分块释放**：先四指、后拇指；先较可信的总尺度/近中节，再处理有独立测量支持的末段；随后才允许有限的掌部根点调整。
6. **联合精修**：只联合优化已通过可辨识性检查的全局参数与每帧姿态，加入标记接触和独立测量；固定设备机械几何，避免所有误差同时漂移。
7. **验证与冻结**：独立动作和前后佩戴一致性通过后发布 profile；失败不自动覆盖已知可用结果。

分块过程仍可能相关，不把顺序优化误认为唯一解证明；最终要检查联合问题的退化。

### 7.2 观测模型与残差

来源 A 下，可用以下联合目标：

`min_(g,x,phi,{q_t}) Σ_(t,f) ρ(||W_p(p_pred−p_obs)||²) + ρ(||W_R Log(R_predᵀR_obs)||²)`

`+ Σ_t ||W_e(z_t − h(q_t; phi))||² + E_measurement + E_contact + E_anatomy + E_temporal`。

- 位置误差单位 m、旋转误差用 SO(3) log 的 rad；用协方差或明确噪声尺度白化，不能直接用未归一化的“米 + 度”混合代价。
- z 可以是经现有四连杆转换的机械观测角；其零位只应用一次。`h_j(q)=a_j·q_(k(j))+b_j+少量同指耦合项` 仅作为可解释近似；不同轴和多关节观测要显式选模型，不默认一对一。
- 角增益符号/范围需要设备/人体独立依据；不允许自由全连接矩阵把错误机械模型拟合掉。
- `E_measurement` 是真实尺寸/外参/标记代理的带不确定度残差；皮肤代理的系统误差不能靠三次重复测量就缩到零。
- `E_contact` 仅在独立标记窗口启用。可采用指腹球/椭球表面间距，或与已知物体表面的距离；接触半径/点位也须测量或有先验，不能与骨长一起完全自由。
- 骨长正值与关节 ROM 用参数边界；姿态相关外展范围、轻度关节耦合、掌弓先验需明确是软约束还是非线性硬约束。
- `E_temporal` 用真实 dt 构造速度/加速度项，只抑制不合理跳变，不得把动作幅度滤掉。跨缺帧/重启不能沿用未说明的连续性。

来源 B 不得直接使用上述“独立位姿 + 独立编码器”对角权重。推荐以原始编码器为随机观测，通过机械模型传播为人体配准约束；或联合建模编码器、派生位姿的交叉协方差，处理其奇异性。简化实现可以选一个统计观测表示，其余只做初始化/诊断，不宣称额外独立精度。

来源 B 的一种不重复计权实现是显式设置每帧潜在真实机械角 `e*_t`：

`E_B = Σ_t ||Σ_e^(-1/2)(e_obs,t − e*_t)||² + Σ_(t,f) ||W_closure Log((T_ES,human)^(-1) · FK_exo,f(e*_t;κ))||² + E_measurement + E_contact + E_anatomy + E_temporal`。

κ 为已校准的机械几何，closure 项描述实际附着/机械模型误差，不是假造第二个独立传感器。若加入机械角—人体角映射，作用在潜变量 `e*_t` 与 q 的关系上，且其误差与 closure 的相关性仍须说明；保守实现先让映射仅用于初始化，独立验证后才增加有证据的残差项。需要联合估计少量 κ 时，使用设备层独立测量约束并检查跨帧相关性，不能由人体骨长共同任意吸收。

若使用传播协方差，派生位姿项约为 `G Σ_e Gᵀ`（G 是机械 FK 的局部 Jacobian），其秩可能不足；应在有效子空间白化/使用适当伪逆并单独建模机械误差，而不是加一个随意小对角数后宣称有 30 个独立位姿测量。

### 7.3 数值求解器

优先使用项目已有 NumPy/SciPy：`scipy.optimize.least_squares(method='trf')`，支持变量边界、稀疏 Jacobian 和鲁棒损失。每帧 q 仅连接对应观测及相邻时序项，全局参数连接多帧，利用该块稀疏结构。

- 先实现并核对解析几何/Jacobian；有限差分可用于验证，不作为未经测量的实时性能保证。
- 固定参数必须移出待优化向量，不能在 `least_squares` 中用相等的上下界冻结；该接口要求各项 `lb < ub`。冻结维只在完整模型状态中保留。
- `method='lm'` 不支持 bounds、稀疏 Jacobian，且只支持 linear loss；不能同时要求 LM 原生支持以上全部约束。
- 若必须严格满足姿态相关的非线性不等式，可用 SLSQP 做受限精修/实时小问题；软惩罚不能称为硬保证，SLSQP 的最终约束也须独立复核。
- 对传感器项可用 Huber/soft-L1；不要无区别地削弱关键尺寸与规范固定约束。可用分组损失或外层 IRLS 保留必要测量权重。
- 上述目标式以几何残差块表示鲁棒核；SciPy 内置 loss 实际逐标量作用，不自动等同 SE(3) 块鲁棒。若需整块降权应显式实现分组 IRLS/对应 Jacobian。可辨识性分析使用原始白化数据 Jacobian，而不是直接把经鲁棒修正且含先验的 `result.jac` 当观测信息。
- 以真实观测噪声、参数尺度、动作覆盖选权重和迭代上限；不承诺更换优化器本身解决不可辨识性。

官方接口依据：[SciPy least_squares](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)。实际集成须以项目锁定版本核对参数，不依赖新版本独有选项。

## 8. 标定后的实时路径和计划代码位置

实时只估计 q（必要时加腕姿态），g 与安装 profile 在会话内固定。使用上帧姿态/速度 warm-start，融合当帧有效观测，维护 ROM 和时序约束；缺少观测时输出相应质量/先验依赖，不用旧姿态冒充新测量。

- 单指观测失效：若编码器仍有效，可做明确标记的降级解；两者都缺失时不能声称该指由当帧测得。
- 时间超限、残差超限、轴方向异常或超 ROM：标记失败/降级，不能只看优化器成功码。
- 识别到佩戴滑移：请求重新佩戴标定，不在线拉长/缩短手指。
- 100 Hz 是已查阅录制的声明频率；10 ms 周期内的实际 IK 耗时必须在实现后实测，当前没有性能通过证据。
- 最终 21 点全部由同一人体 FK 产生；显示、导出、Hand2 使用同一版本的点，无显示后处理、指尖吸附或 CMC 中点替换。

建议 Module / Interface 划分（以下均为拟议位置，尚未创建实现）：

| 拟议位置 | 职责与 Interface |
|---|---|
| `core/human_hand.py` | 固定人体拓扑/几何；`forward(q, profile)` 同时产生 21 点、远节 frame、关节 frame 及 Jacobian |
| `core/hand_observations.py` | 规范化五指位姿和有效位；显式描述 frame、单位、时间与派生依赖，不改写原始证据 |
| `core/hand_calibration.py` | `calibrate(sequence, measurements, hardware_profile)` 返回人体 profile、佩戴 profile 和可辨识性/验证报告 |
| `core/human_hand_ik.py` | `solve(observation, previous_state, fixed_profile)` 返回人体姿态、点和质量，不读设备/不写文件 |
| 现有 `recordings.py`、`live.py`、`usb/` | 保留原格式读取；有真实 SDK 契约后再新增位姿输入 Adapter 和独立时间信息，不能补造旧录制字段 |
| 现有 `calibration.py` | 继续负责设备零位，不掺入人体骨长；向新流程提供已明确语义的设备 profile |
| 现有 `engine.py`、`processor.py` | 显式接入新人体 Module；保存 profile 与版本，正式切换时删除旧手型路径和补偿，避免运行时两套真值 |
| 现有 `web/` | 采集向导、尺寸输入、标定质量与骨架对照；不承担求解或修点 |

数据建议：在新版本录制/结果中保存 `/observations/tips/{position_m,quaternion_xyzw,valid,covariance}`、原始/对齐时间、`provenance`，以及 `/calibration/{human_profile,donning_profile,hardware_reference,fit_report}`。旧 HDF5 保持只读原语义；没有位姿的旧数据必须标记 encoder-only/derived-FK，不能升级成独立 6DoF 录制。所有新结果记录输入哈希、设备/人体/佩戴 profile 的版本和内容哈希。

## 9. 误差验证和发布门槛

按三层报告，不混成一个“误差”：

1. **观测拟合误差**：末端 position/orientation、机械角残差；说明来源 A/B。派生 FK 的残差只说明与机械模型一致。
2. **人体几何与运动误差**：固定骨长不变量、测量先验偏差、中间关节代理位置、人体 ROM、姿态连续性、拇指对掌和掌弓运动。
3. **独立外部准确度**：未用于标定的手动/标记点/已知物体几何或其他独立测量。重复处理同一录制、重投影到自身模型不能作为外部准确度。

推荐试采时讨论的目标，不是已验证承诺：

| 指标 | 建议初始门槛/判断 | 限制 |
|---|---|---|
| 骨长随帧变化 | 数值精度内为零；几何参数完全不参与在线优化 | 含掌弓时检查真实固定骨段，不检查任意腕→MCP距离 |
| 独立末端位置 | 在测量系统精度足够时争取 P95 ≤5 mm | 若参考自身误差已达该量级，先改测量，不用拟合值替代 |
| 独立末端朝向 | 初始目标 P95 ≤5° | 比较同一物理 frame，先去安装旋转 |
| 中间 PIP/DIP 代理位置 | 初始目标 P95 ≤8 mm，并报告代理标记不确定度 | 不能称内部骨中心准确度；最终门槛需用户确认 |
| 同用户重复标定 | 骨段变化争取 ≤max(2 mm,5%)，检查系统性偏差 | 宽置信区间或边界解直接标弱辨识 |
| 无动作抖动/延迟 | 报告位置 RMS、角速度异常率和端到端延迟分位数 | 不能只用强平滑取得低抖动，须同时评估运动滞后 |
| 重新佩戴 | 固定人体骨长，只重估佩戴参数后仍通过验证 | 若必须改骨长才能通过，优先判安装/模型有问题 |

留出验证按完整动作段或独立 take 划分。至少检查：伸展、桌面手形、钩形、半握拳、全握拳（舒适范围）、四组捏合与故意不接触、快慢屈伸、小指掌弓。每指分别报告均值/中位/P95/最大值、失效率，不只给全手平均。

## 10. 本轮已经执行的数值证据

只读实验脚本：`.cache/bone-calibration-research/audit.py`；结果：`.cache/bone-calibration-research/audit.json`。运行命令：

```sh
.pixi/envs/default/bin/python .cache/bone-calibration-research/audit.py
```

这些是模型/合成实验，不是实物精度验证，也不是新标定器实现。

1. 左右实际 URDF：各 22 links、21 q；五末端空间位姿对 q 的有限差分 Jacobian 为 `30×21`，在选取的非零模型姿态下两侧秩均为 21。证明该派生表示没有新增 30 个独立信息维度；不代表所有实际姿态均无奇异。
2. 固定随机种子 42、80 个平面指链姿态，已知人体关节角：对 `[近节,中节,末节,轴向安装偏移]` 的位置 Jacobian 秩为 3/4，最小奇异值约 `1.08e-15`。末节 +7 mm、安装偏移 −7 mm 后，末端位置最大差 `1.39e-17 m`，朝向差 0；加入一项独立末段长度观测后秩为 4。
3. 单帧反例：`[45,27,30] mm` 与 `[50,22,30] mm` 两套骨段配合不同合法关节角，末端位置误差约 `1.96e-14 mm`、朝向差 0，但 PIP 位置相差 `5.245 mm`。这是“仅末端吻合不足以验证中间关节”的反例，不声称任意多帧数据都有完全相同的第二组解。

## 12. 开源方案与 MANUS 官方流程核查

核查方式：阅读第一手官方文档、固定 commit 源码和许可；没有安装或运行以下研究仓库，没有取得 MANO 模型资产。源码能力已核查，实际硬件精度和性能没有实测。网页访问日期为 2026-10-12；MANUS 提供文档版本，没有可核实的源码 commit。

### 12.1 MANUS：借鉴流程，不假定其求解器开源

官方各代流程不能混写：

| 产品/软件 | 实际流程 | 对本项目的价值 |
|---|---|---|
| Quantum Mocap，文档 3.1.1 | 非金属台面平放 → 握拳 → 指尖反复触掌根 | 多姿态采集及预览/准备/录制状态机参考 |
| Metagloves Pro，Core 3.1.1 | 平放 → 握拳 → 连续张合 → 拇指触指关节/拳峰 | 比单一静态零位多了运动和拇指几何约束 |
| Pro，自 Core 3.2.0 起，文档 3.2.1 | 前四步 + 拇指分别与食/中/无名/小指轻捏，分别保持约 3 秒 | 可借鉴本流程的四组接触采集；官方强调不可用力挤压 |

官方产品规格页仍可能写旧“四步”；本轮以版本化标定文档为准。[M1–M3]

手测页面明确区分各段长度、distal thickness 和 **tip-to-casing**。它建议：整体弯曲跟随良好但捏合不合时，优先调整 tip-to-casing，而不是改骨长。要求左右手分开测、通常沿手背、用 mm、至少重复两次并校核整指总长。[M4]

本报告步骤 1 的 MCP 横向跨度是本项目的解剖代理量，不冒充 MANUS 的外轮廓掌宽；若使用厂商/人口数据，必须保留原测量定义。MANUS 的掌宽是 MCP 下方最宽处，wrist-to-MCP 是腕纹中心到关节位置，不能直接当作医学掌骨长。

MANUS SDK 的两类 raw 数据：

- `ManusSDKTypes.h` 的 `RawSkeletonInfo` / `SkeletonNode`：Core 已估计的人体骨架；raw 是相对于目标重定向而言，不是原始测量。可受 pinch/casing compensation 影响。
- `RawDeviceData`：`sensorData[5]` 的传感器变换，另有 IMU rotation；SDK 文档将原始传感器位姿流限定为 **Pro 且启用 raw 许可**，位置参考手背壳体内主线圈。它不是人体指尖坐标，也不是电磁 ADC 电压。
- `sdk/Calibration.cpp` 的 `GetNumberOfSteps/GetStep/Start/ExecuteStep/Finish` 调用 `CoreSdk_GloveCalibration*`；`SaveToFile/LoadFromFile` 获取/恢复不透明标定字节。它公开了调用流程，没有公开骨长优化方程。
- `sdk/Streams.cpp` 的 `OnRawDeviceDataStreamCallback` 和 `sdk/SkeletonsRaw.cpp` 可接收合法 MANUS 设备数据；未查到将任意自制编码器手套数据送入其人体标定器的公开通用入口。[M5,M6]

因此可复用**动作组织、测量项目、安装偏移分层和 profile 生命周期思想**；不能声称拿到 Hand Solver 3、双手拇指细化或补偿算法源码。SDK 是商业许可，示例源码分发也有条件，不按 MIT/Apache 处理。[M7] 官方没有公开证明内部算法完全不含学习方法；本项目自主优化路线不依赖这一点。

### 12.2 hand-kinematics：轻量 FK 参考，不是骨长标定器

固定仓库：`ErnestWang31/hand-kinematics@c4ce375c81d805c6cf880743f530dadae752658b`；根许可 MIT。[H1,H2]

实际可复用文件/符号：

- `hand_kinematics.py`：`HandModel.from_yaml/_build/fk/_fk_finger/_fk_thumb/violations/clamp`。输入角度字典、手长 HL、手宽 HB 与每指 scale；输出每指 `(5,3)` 的位置，单位 m。
- `_build` 的长度来自 `segment_ratio × HL × scale[finger]`；同一手指各节共用 scale，不能独立拟合各节比例。
- 实际 FK 使用四指各 4 角、拇指 6 角，共 **22 个角**；不能照抄文件自述“26DoF”。其 22 的组成与本报告拟议 22DoF 不同，不能按数组维数直接互换。
- `hand_model.yaml` 有关节限位、DIP/PIP 关系和掌弓配置，但 ring/little `metacarpal_arch` 没有进入 Python FK；`clamp()` 也不是把所有耦合约束都实现了的优化投影。
- `hand_export.py` 的 `frames` 通过小角度扰动和向量叉积推导模型轴；不是实测人体转轴，也不是五指传感器 6DoF 接收实现。[H2,H3,H5]

**缺少**多帧观测输入、人体骨长共享变量求解、安装外参辨识、末端 IK 和本项目的机械观测模型。可借鉴 NumPy FK 的组织与显式参数设计，但应扩展为真正可独立控制各段长度、返回末端旋转和 Jacobian 的人体 Module；不需要引入 CAD/Onshape 依赖。

人体比例的证据边界：其来源包括 Greiner 人群统计、作者对食指的修正及当前 commit 对拇指的修改。原始报告以皮肤掌纹/照片点作为关节中心代理；仓库用腕中心到 MCP 的径向构造也不等于原报告沿指轴到腕纹基线的测量。比例可作初始化/弱先验，不能当本用户真值。[H3,H4,H6]

### 12.3 manotorch：可微人体模型，不是自由骨长标定器

固定仓库：`lixiny/manotorch@a2a70c591f91551078b7bb2af9b5d9f275b626e0`。[T1]

实际源码能力：

| 文件/符号 | 实际输入输出/能力 | 本任务缺口 |
|---|---|---|
| `manolayer.py::ManoLayer.forward` / `skinning_layer` | 无 PCA 轴角 pose `(B,48)`，通常 beta `(B,10)`；输出 joints `(B,21,3)`、verts `(B,778,3)`、transforms `(B,16,4,4)` | beta 是统计形状坐标，不是 15 个独立骨段长度；无人体—外骨骼安装模型 |
| `axislayer.py::AxisAdaptiveLayer` | 用关节位置和 FK 变换构建 twist/spread/bend 轴 | 不是个体实测转轴 |
| `axislayer.py::AxisLayerFK.forward/compose` | 变换与解剖欧拉角互换；轴以零 pose/零 beta 模板初始化 | 个体 beta 不等于已完成个体轴标定 |
| `anatomy_loss.py::AnatomyConstraintLossEE` | 对解剖角范围施加软惩罚 | 无骨长、末端偏移、编码器噪声/耦合残差 |
| `scripts/simple_anatomy_loss.py` | 用 Adam 优化单姿态角张量，形状固定 | 不是多帧个性化标定，也不是训练网络 |

21 点重排在源码中存在；五个 tip 是网格表面顶点。16 个 transforms 的顺序与 21 点顺序不同，而且没有五个独立指尖刚体。不能直接把 `transforms_abs` 当五指传感器位姿。`center_idx=None` 不等于自动减去腕点；指定 `center_idx=0` 才进行对应腕中心化。[T2–T4]

**非学习边界**：manotorch 前向计算和对 pose/beta 的优化不要求训练神经网络，但 MANO 的形状/姿态基本身来自扫描数据学习。严格不依赖 learned prior 时不选 MANO；即使允许固定统计先验，10 维 beta 也不应被称为独立量得的各节骨长。[T2,T6]

**许可不能只看仓库徽标**：当前根 LICENSE 是 Apache-2.0，但父提交为 GPLv3、当前 `setup.py` 仍标 GPL，且存在来自 manopth 的历史；直接依赖的 `mano/webuser/smpl_handpca_wrapper_HAND_only.py` 保留研究用途许可声明。MANO 模型资产另受官方非商业/分发限制，商用需单独授权。本轮不裁定再授权效力，也不下载/分发模型。[T5–T7]

结论：作为可选学术比较模型有价值；本项目主线优先显式几何骨架，避免把 beta 子空间、网格成本和许可问题引入必需流程。

### 12.4 KinePose：固定人体链的方向 IK，不是尺寸标定

固定仓库：`KevGildea/KinePose@d045e34137b4c09c06b79e9a8a2205439dcf27a1`；根许可 GPLv3。[K1,K2]

- `6DOF/kinematics.py`：`FK_MDH/Rev_FK_MDH`、`IK_vector_mapping`、`IK_opt_frames`。在固定 chain 平移上优化各节点三轴旋转，变量按整圈比例乘 `2π`；不是各指解剖 DoF 直接接口。
- `IK_vector_mapping` 比较模型骨向量与输入骨向量的夹角，损失为角度平方和，没有绝对末端位置、末端传感器旋转、共享骨长或安装外参项。方向损失对全局正尺度不敏感，不能单独确定绝对骨长。
- `IK_opt_frames` 使用 SciPy SLSQP 与上一帧 warm-start；可参考有界优化思想，但不建议直接移植 GPL 代码作为本项目主干。
- `6DOF/KinePose.py` 的 GUI 输入是 `(T,17,3)` 点，删除 index 9 后为 16 点；不是五组末端 SE(3)。用户自定义链不意味着已有手部个体标定器。
- `Calibration/Knowable_Intrinsics/Intrinsics.py` 的 `calibrate_camera` 和 `PnP.py` 的 `save_calibration` 是棋盘内参/PnP 外参估计，不是人体骨长标定。[K2–K4]

源码还存在应避免照搬的细节：`IK_vector_mapping_temporal` 重塑 `weights_all` 后，循环最终把一帧 `weights` 传给 `loss_dEAs(weights,len(poses))`，并非完整时序矩阵；按静态代码分析会错误地跨参数差分，长序列可能越界。本轮未运行复现该缺陷。后处理 Savitzky–Golay 平滑也不自动保持原约束。故不能将其时序优化或“6DOF”命名当成本项目实时人体 IK 的已验证能力。[K2,K3]

整体项目含 YOLO/MotionBERT 视觉前端；这些不属于本任务可用路线。仅独立的经典 IK 数学思路可供参考。
