# 架构、职责与维护

## 运行边界

项目运行所需算法、左右手URDF、网格、配置都保存在本目录。源项目仅作为开发时只读来源，运行不访问原项目，不通过软链接引用外部资产。来源记录见根目录 `provenance.json`；许可证保存在 `licenses/`。部分本地来源未提供完整再分发许可证，不应把本机可使用解释成已获得公开再分发授权。

本工具不包含机器人SDK或板端标定写入。默认实时模式读取DGST USB，只有显式准备请求才通过ADB调用板端已安装的启动脚本；显式无相机兼容模式则只读ADB编码器与出厂身份，不启动相机/DGST、不重配USB。两种模式均不部署固件、不访问原网关。原始录制可以在项目外，只读打开；新增采集、标定、快照、单手结果及缓存只写项目内部。联合结果按录制容器写入任务根 `processed.h5` 或采集文件同目录 `<源文件stem>.processed.h5`；碰撞后处理在输入同目录另存，不改源文件。服务默认仅监听127.0.0.1:8091，并限制Host及修改请求同源访问。

依赖由Pixi的 `pixi.toml` / `pixi.lock` 管理。Python、MuJoCo、Pinocchio、NLopt、NumPy、SciPy、libusb及Node来自conda-forge；不要额外pip安装pin替代Pinocchio。ADB使用锁定的adbutils平台wheel自带二进制；USB设备访问权限仍由宿主系统管理，不自动修改udev或使用sudo。前端three/vite由Pixi环境中的npm按 `web/package-lock.json` 安装。前端构建资源与模型在本机提供，不使用CDN。

| `engine.py` | 将独立CS与共用解剖J定义装配到该侧机械参数，保留该侧URDF输出顺序；三阶段顺序数值链及阶段错误 | HTTP、磁盘结果、浏览器渲染 |
| `core/` | V21机构、FK、固定手型骨架拟合的本地纯计算实现 | 网络采集、旧项目兼容入口 |

| `processor.py` | 全帧顺序处理、HDF5发布、元数据快照、结果读取 | 标定姿态选择、前端交互 |
| `models.py` | 项目内URDF解析与本地网格URL | 重新求解关节轨迹 |
| `server.py` | 本机HTTP接口、文件打开、任务进度、固定目录保存入口 | 自创另一套数值算法 |
| `cli.py` | Pixi命令行启动、inspect、process | 额外维护一套处理逻辑 |
| `web/src/main.js` | 导入/标定/处理/同步时间轴交互 | 复制Python求解链 |
| `web/src/scene.js` | URDF真实模型与21点骨架显示 | 根据原始角猜零位或机器人姿态 |
| `assets/` | 左右V21与Hand2模型及网格 | 用户采集结果 |
| `config/` | 模型/重定向参数和独立设备零位 | 原始录制 |
| `data/raw/` | 实时动作、各组标定采样、原始元数据和未完成证据 | 导出关节或关键点 |
| `data/processed/` | 用户正式处理结果 | 临时调试脚本 |

## 核心不变量

1. 读入统一为21路原始绝对角；零位和传感器方向在四连杆上游应用一次。
2. 传感器方向、机构输入方向和URDF轴向映射是不同概念，不合并或重复补偿。
3. 人手骨架与Wuji求解使用顺序历史状态；每次全段处理新建Engine，不复用UI拖动预览状态。
4. 有效性分阶段传播，失败不返回上一帧/初值冒充成功。vendored优化器将NLopt错误、非有限及越限结果显式报告，不污染成功的warm-start。
5. 处理文件只有完整收尾后才发布；单手不覆盖已有文件，联合结果仅可原子替换同 schema/version/录制身份的旧结果。所有原始采样时刻保留，失败行不删除。
6. 标定按手侧和设备ID命名，处理仍检查文件内容与接线；名字相似不代表可通用。
7. 回放只读取结果，校验模型指纹。结果不依赖当下固定目录中标定文件的内容。
8. 左右模型与配置分别存在；左手骨架镜像规范化由数值模块负责，Web不能再盲目镜像一次。
9. 部分V21机构参数沿用既有估计值，软件链可运行不代表几何尺寸、所有传感器方向或实物控制已验收。
10. 网页刷新不是采集时钟；后台持续接收，预览只取最新帧，动作录制保留接收到的每帧。兼容模式交付号与真实驱动扫描号分开记录，不用连续交付号掩盖物理跳扫。
11. 会话ID在重连后更换；标定和录制请求绑定会话。所有修改型实时请求串行执行，避免采样期间切换手套。
12. DGST视频必须独立排空以保持固件会话正常，本工具不保存视频。断连/超时不能继续展示最后姿态冒充新数据。
13. 人手拟合后将1号拇指CMC重建为0号腕点与2号MCP的中点，其他20点不变。重建后的同一套MediaPipe编号21点用于显示、导出和Hand2输入；不隐藏点、不画平滑曲线，不将几何估计冒充检测结果。
14. Hand2自碰撞优化默认关闭；显式启用时，活动碰撞对必须满足各自间隙及容差，滤波输出也重新校验。失败不得提交warm-start或滤波历史。实际碰撞策略随新结果保存，关闭时不承诺防穿模，历史文件不自动获得新约束。
15. 实时手侧必须由用户明确选择；设备声明仅作独立证据。会话有效手侧决定模型/标定，原始角、板端已应用标定和实际CS排列不被覆盖；带版本的主机会话选择贯穿采样、录制与重载，普通离线事实冲突仍拒绝。
16. 兼容采集必须显式选择，不从DGST失败自动回退；角度只能由真实raw counts换算。自建ID和元数据标为host_generated，真实板号、出厂接线及其来源独立保存，损坏出厂记录不当作缺失。
17. 标准J唯一来源是`joint_channels._JOINTS`中的解剖定义：侧摆、掌骨屈伸、次末节、末节各五路从拇指到小拇指，最后小拇指CMC。两侧按joint_name补入对应source_channel，保留自身direction/scale、机构参数和URDF顺序；不再沿用旧右手J1/J6倒置语义。左右CS表独立；码表、标定及数值链按CS定位原始列，原始采样/历史零位存储顺序不变。机械JSON经`engine.profile(hand)`装配后交底层解析器。

## 验证入口

```bash
pixi run test
pixi run web-build
pixi run serve
```

测试临时目录限制在 `.cache/pytest-tmp`。验证应覆盖输入角度语义、身份冲突、跨0度零位、窗口连续性、原子覆盖，以及左右手真实数值链和浏览器三栏表面。

合成样本只用于算法/接口边界和端到端软件冒烟，不能代替用户SD录制或实物标定验收。正式数据验收还需用户实际录制及明确零位姿态。不得把验证生成的标定作为真实手套默认标定交付。

## 文档管理规则

- 根README只保留入口、启动方式与导航，不复制详细字段或完整设计。
- `workflow.md`只维护操作与错误处理；`data-format.md`维护格式、坐标、单位及有效性；本页维护模块职责与依赖边界。
- `api-contract.json`维护前后端契约；修改HTTP格式时同步服务端、前端和该文件。
- 来源与许可证只在provenance/licenses维护，不在多份说明复制来源清单。
- 不新建同一主题的“最终版/新版/v2”文档；直接更新唯一职责文件。
- 临时脚本、截图和机器验证产物放`.cache`，不得伪装成用户正式结果；完成后移除不再需要的脚本与合成设备标定。
