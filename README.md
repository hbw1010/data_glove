# data_glove — V21 左右手标定与离线处理工作台

用于 V21 数据手套的本机 Web 工具，支持 USB 实时采集、六步零位/方向标定、已有录制导入，以及 V21 外骨骼关节、人手 21 点骨架、Wuji Hand2 关节的导出与同步回放。

## 主要功能

| 功能 | 说明 |
|---|---|
| 实时采集 | 通过 USB DGST 或 ADB 仅编码器兼容模式读取实体手套，查看实时关节读数并保存动作 |
| 六步标定 | 按手侧和设备身份建立零位与方向标定，保存采样证据和标定文件 |
| 离线导入 | 读取已有 SD 录制、双手采集 HDF5 和对齐 HDF5，校验输入身份与角度语义 |
| 三阶段处理 | 从编码器角度计算 V21 外骨骼关节，再拟合人手骨架，最后重定向到 Wuji Hand2 |
| 结果导出 | 输出 HDF5，保存时间戳、各阶段结果、有效性及处理元数据 |
| 同步回放 | 在本机网页对照外骨骼、人手骨架和 Hand2，支持关联已有录制的视频 |

## 数据处理流程

```text
实体手套采集 / 已有录制
          ↓
读取原始编码器角度与设备身份
          ↓
应用对应手侧、设备的标定
          ↓
V21 外骨骼关节 → 人手 21 点骨架 → Wuji Hand2 关节
          ↓
导出 HDF5 / 网页同步回放
```

项目面向手套数据标定、离线处理和结果检查，不提供机器人在线控制。

## 安装与启动

当前 Pixi 配置支持 **Linux x86_64（`linux-64`）**。在已安装 Pixi 的机器上，进入项目目录执行：

```bash
pixi install --locked
pixi run start
```

浏览器打开 <http://127.0.0.1:8091>。`start` 会先执行 npm 依赖安装和前端构建，再启动服务。关闭服务使用 `Ctrl+C`。

前端已构建且没有修改时，可直接启动：

```bash
pixi run serve
```

需要视频回放时，另行安装 FFmpeg，并检查以下命令可用：

```bash
ffmpeg -version
ffprobe -version
```

推荐通过 Pixi 运行本项目；仅执行 `pip install .` 不会安装完整运行环境或构建前端。

## 基本使用

1. **选择数据来源**：连接实体手套并明确选择左/右手，或在页面填写已有录制的文件/目录路径。
2. **准备标定**：完成六步标定，或使用与手侧、设备身份匹配的已有标定。不能借用其他设备的零位。
3. **导出结果**：检查输入和预览，明确点击导出后开始处理。
4. **同步回放**：打开处理结果，查看外骨骼、人手骨架和 Hand2 三种输出。

支持双手任务目录及 `*.v21glove.h5` 采集文件。`*.aligned_60hz.h5` 使用页面中的“对齐 HDF5 手动参数导入”，分别上传左右手完整标定 JSON，并明确选择角度约定。详细步骤见[操作流程](docs/workflow.md)。

### 实时模式

- **DGST 模式**：显式启动板端已有采集程序，可能短暂重枚举 USB 并接管板端相机。
- **仅编码器兼容模式**：相机不可用时可显式选择，通过 ADB 只读真实编码器并生成独立软件身份，不启动相机或 DGST。

两种模式均不保存视频，不刷固件、不写板端标定、不控制机器人。已有录制的视频回放是独立功能。

## 文件与输出位置

| 路径 | 内容 |
|---|---|
| `src/glove_calibrate/` | 后端、采集、标定和处理代码 |
| `vendor/wuji-retargeting/` | 随附的 Wuji 重定向算法 |
| `assets/` | 左右手模型与网格 |
| `config/` | 机械与重定向配置 |
| `config/dataglove/v21/zero/` | 设备标定，命名为 `left_<手套id>.json` 或 `right_<手套id>.json` |
| `web/` | 前端源码、依赖锁文件和构建产物 |
| `data/raw/` | 实时动作及标定采样证据 |
| `data/processed/` | 单手处理结果 |
| `docs/` | 操作、格式、架构和接口文档 |
| `tests/` | 回归测试 |

双手目录任务在任务根目录输出 `processed.h5`；采集或对齐 HDF5 在源文件同目录输出 `<源文件stem>.processed.h5`。原始输入只读，断连产生的未完成采集文件不会作为正式录制发布。

## 项目独立性

本项目的算法、左右手模型、网格和配置均保存在项目目录内，运行不需要其他本地工程，也不需要启动旧网关。`vendor/wuji-retargeting/` 是随项目保存的算法代码，无需另外克隆源项目。

“独立”指源码和资源自包含，仍需安装第三方运行环境，并按功能准备输入数据或实体手套：

| 依赖 | 用途与管理方式 |
|---|---|
| Pixi | 安装环境、运行项目任务；需在宿主机预先安装 |
| Python 3.12、NumPy、SciPy、MuJoCo、Pinocchio、NLopt、h5py、FastAPI 等 | 数值计算、文件处理与本机服务，由 `pixi.toml` / `pixi.lock` 管理 |
| Node.js 22、Three.js、Vite | 前端构建；Node.js 由 Pixi 管理，前端包由 `web/package-lock.json` 锁定 |
| libusb、ADB | 实时设备接入；libusb 由 Pixi 管理，ADB 使用 adbutils 包内二进制；USB 访问权限由宿主系统管理 |
| FFmpeg（`ffmpeg`、`ffprobe`） | 已有视频的封装、探测和回放；**当前未纳入 Pixi 配置及锁文件，需额外安装并加入 PATH** |
| 原始录制、对应设备标定 | 离线处理所需输入，按实际任务提供 |
| 手套及已有板端工具 | 仅实时采集需要；DGST 模式使用已有启动脚本，兼容模式使用板端编码器读取工具 |

前端资源在本地构建和提供，不使用 CDN。首次安装环境和前端依赖需要联网；离线部署需提前准备好依赖和构建产物。

## 数据处理依赖

完整离线导出会初始化外骨骼、人手骨架和 Hand2 三个阶段，因此需要整条数值链的依赖，不能只安装文件读取库。以下资源均随项目保存，表中的 `<hand>` 为 `left` 或 `right`。

| 处理阶段 | 软件依赖 | 必需数据、配置或模型 |
|---|---|---|
| 读取与校验录制 | NumPy、h5py（HDF5 输入）及项目格式适配代码 | 原始角度、时间戳、手侧、设备身份、CS 通道映射和角度约定；目录录制还需关联元数据 |
| 标定与外骨骼关节换算 | NumPy、项目内 `core/` 机构算法和 `joint_channels.py` | 对应设备的完整标定、`config/dataglove/v21/<hand>.json`、`assets/data_glove_v2.1_urdf/` 中对应手侧的 URDF |
| 人手 21 点骨架拟合 | NumPy、MuJoCo、项目内手型拟合算法 | 对应 V21 URDF 及其引用网格、`config/retargeting/v21_<hand>_mano_morphology.json` |
| Wuji Hand2 重定向 | NumPy、Pinocchio、NLopt、PyYAML、随附 `wuji_retargeting` | `config/retargeting/official/<hand>.yaml`、`assets/wuji-hand2/body/urdf/<hand>.urdf` |
| Hand2 自碰撞约束（可选功能） | Coal、Pinocchio、NLopt | Hand2 URDF 引用的碰撞几何、对应 YAML 中的碰撞策略；默认关闭，需显式启用 |
| HDF5 结果写入与来源记录 | h5py、NumPy；当前实现还读取 SciPy 等包的安装版本 | 可写输出目录，以及项目内代码、配置和模型文件，用于记录标定快照与资源指纹 |

**安装方式**：使用 `pixi install --locked` 安装整套环境，以 `pixi.lock` 为实际版本依据。Coal 已由锁定环境中的依赖链带入；当前求解器模块会直接导入 Coal，即使关闭自碰撞约束也不能将其从运行环境删除。不要另外用 `pip install pin` 替换 Pixi 管理的 Pinocchio。

`wuji_retargeting` 来自本项目的 `vendor/wuji-retargeting/`，Pixi 通过 `PYTHONPATH` 加载它。请使用 `pixi run process ...` 等项目命令；直接在系统 Python 中运行可能无法找到该模块或原生数值库。

### 每次处理前需要准备的输入

- **原始录制及元数据**：目录型录制应保留完整目录，不要只复制角度文件。处理器需要确认手侧、设备身份、通道映射和角度语义；内部数值链接收 21 路 `[0, 360)` 度原始绝对角及对应时间轴。
- **匹配的完整标定**：提供对应手侧、设备及接线的标定。命令行可用 `--calibration` 显式指定；未指定时先查固定标定目录，无匹配文件时尝试录制中可用的内嵌标定。仍无可用标定则不能正式处理。
- **对齐 HDF5 的手动参数**：使用专用导入入口，提供左右手完整标定 JSON 和各自角度约定；已有对齐文件作为输入，本项目不负责生成这份对齐输入。
- **完整模型和配置**：保留上述 `assets/`、`config/`、`vendor/` 文件。设备标定与机械参数、手型参数、重定向参数用途不同，不能互相替代。

具体输入格式和字段要求见[数据格式](docs/data-format.md)。

### 核心处理与附加功能的依赖边界

- **仅离线计算与 HDF5 导出**：不需要连接手套、启动旧网关、连接机器人或运行前端构建；命令行直接使用上述数值链。依赖安装完成后，计算过程不需要访问源项目或联网服务。
- **网页操作和三维回放**：另需 FastAPI、Uvicorn 及已构建的 `web/dist/`；Node.js、Vite 用于构建，Three.js 用于浏览器显示。
- **关联视频回放**：另需原始视频及对应关联信息、FFmpeg/ffprobe。它们不参与关节和骨架求解；对齐视频还需要相应的 alignment report/CSV，命名与校验规则见数据格式文档。
- **实时采集**：另需 libusb、ADB、USB 权限和板端已有工具；离线处理已有录制无需实体设备。
- **人手骨架输出**：使用项目内固定参数化手型，不需要下载标准 MANO 模型文件，也不运行 MediaPipe 图像检测；“MediaPipe 21 点”表示关键点编号约定。

## 迁移到其他机器

- 保留完整源码目录结构，尤其是 `src/`、`vendor/`、`assets/`、`config/`、`web/` 以及依赖清单和锁文件。
- 在目标机器重新执行安装和构建命令。`.pixi/`、`web/node_modules/`、`web/dist/` 和 `.cache/` 可重新生成，无需直接搬运旧环境。
- 数据和设备标定需要单独核对、备份；`data/` 和 `config/dataglove/v21/zero/*.json` 已被 `.gitignore` 忽略，仅复制受 Git 管理的文件可能遗漏它们。
- 页面当前预填原开发机的数据目录。迁移后，将“任务大目录”和“录制文件 / 目录”改为实际路径；这些是输入数据位置，不是外部源码依赖。
- 需要关联视频回放时，同时保留对应视频及关联元数据，并确认其中的路径在目标机器有效。
- 需要实时采集时，确认 USB 访问权限及板端已有程序可用；项目不会自动部署板端固件或工具。

```bash
# 检查录制（将路径替换为实际输入）
pixi run inspect --recording /path/to/recording

# 使用匹配的设备标定处理录制
pixi run process --recording /path/to/recording

# 运行回归测试
pixi run test

# 重新安装前端依赖并构建
pixi run web-build
```

## 功能边界

- 左右手分别维护物理 CS 映射、零位、方向、比例和模型，不混用设备标定。
- 本工具中的“MANO”指拟合的人手 21 个骨架关键点，不包含标准 MANO pose/betas 或网格。
- 软件测试和合成样本验证不能替代实际手套方向、机械尺寸和真实录制验收。
- 算法与模型来源及许可证见 `provenance.json`、`licenses/`；随项目保存不代表获得额外的再分发授权。
